软件工程。

软件工程是将系统化、规范化、可量化的方法应用于软件开发、运行和维护的过程，即将工程化方法应用于软件；同时也研究这些方法本身。

评分：系统化、规范化、可量化 2 分；开发、运行、维护 1 分；工程化方法 1 分。

可用性。

可用性是衡量特定用户在特定环境中使用系统完成任务时是否容易、有效并感到满意的质量属性，常从易学性、效率、易记性、容错性和满意度衡量。

评分：定义 1 分；易学性、效率、易记性、容错性、满意度中写出三项得 2 分。

解释耦合与内聚。

耦合描述模块之间依赖的强弱，耦合越低越有利于独立修改和复用；内聚描述模块内部各元素围绕同一职责结合的程度，内聚越高越好。设计目标通常是高内聚、低耦合。

评分：耦合 1 分；内聚 1 分；高内聚低耦合 1 分。

参与者与用例

主要参与者：患者，以及场景中的管理员或外部系统。核心用例：查询号源、预约挂号、取消预约。

需求层次

public interface CancellationStrategy {
    Money refundAmount(Appointment appointment);
}

public final class NormalCancellationStrategy implements CancellationStrategy {
    @Override
    public Money refundAmount(Appointment appointment) {
        // 本策略只实现一种规则
        return Money.zero();
    }
}

public final class StrategyContext {
    private final CancellationStrategy strategy;

    public StrategyContext(CancellationStrategy strategy) {
        this.strategy = strategy;
    }
}
  • OCP：新增规则时增加具体策略，不修改 Context。
  • DIP：Context 依赖策略接口。
  • SRP：每个策略只负责一种算法。
  • 优点是消除复杂条件并便于独立测试；缺点是类数量增加，配置层必须选择策略。
