软件工程。

软件工程是将系统化、规范化、可量化的方法应用于软件开发、运行和维护的过程，即将工程化方法应用于软件；同时也研究这些方法本身。

评分：系统化、规范化、可量化 2 分；开发、运行、维护 1 分；工程化方法 1 分。

重构。

重构是在不改变软件外部可观察行为的前提下，调整内部结构，以提高可读性、可维护性和可扩展性的过程。

评分：不改变外部行为 1 分；调整内部结构 1 分；质量目标 1 分。

测试驱动开发（TDD）。

TDD 是先写一个失败的自动化测试，再编写刚好使测试通过的代码，最后在测试保护下重构，并不断重复红、绿、重构循环。

评分：先写测试、使测试通过、重构各 1 分。

参与者与用例

需求层次

策略模式类图参考
public interface ConflictStrategy {
    boolean hasConflict(CourseArrange arrange);
}

public final class TeacherConflictStrategy implements ConflictStrategy {
    @Override
    public boolean hasConflict(CourseArrange arrange) {
        // 本策略只实现一种规则
        return false;
    }
}

public final class StrategyContext {
    private final ConflictStrategy strategy;

    public StrategyContext(ConflictStrategy strategy) {
        this.strategy = strategy;
    }
}
  • OCP：新增规则时增加具体策略，不修改 Context。
  • DIP：Context 依赖策略接口。
  • SRP：每个策略只负责一种算法。
  • 优点是消除复杂条件并便于独立测试；缺点是类数量增加，配置层必须选择策略。

改进代码

boolean overlaps(TimeSlot a, TimeSlot b) {
    return a.day().equals(b.day())
            && a.start().isBefore(b.end())
            && b.start().isBefore(a.end());
}

boolean hasStudentConflict(List<Course> selected, Course target) {
    return selected.stream().anyMatch(c -> overlaps(c.slot(), target.slot()));
}
