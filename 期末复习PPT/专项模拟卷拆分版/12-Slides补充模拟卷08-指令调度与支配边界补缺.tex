\addcontentsline{toc}{subsection}{二、资源受限 List Scheduling（20 分）}


给定依赖 DAG，边表示前驱完成后后继才能执行：

\begin{quote}
\footnotesize
\begin{verbatim}
A -> C
B -> C
C -> E
D -> E
E -> F
\end{verbatim}
\end{quote}

每条指令的执行延迟：

\begin{quote}
\footnotesize
\begin{verbatim}
A=2, B=1, C=3, D=1, E=2, F=1
\end{verbatim}
\end{quote}

目标机每周期最多发射两条指令，但每周期最多只能发射一条延迟大于 1 的指令。

\noindent 1. 按“若指令在周期 t 发射，则在 t+latency 时结果可用”的规则，计算无限资源下每个结点的最早发射周期。\\
\noindent 2. 计算从每个结点到出口的最长延迟，作为调度优先级。\\
\noindent 3. 按优先级从大到小进行 List Scheduling，给出每周期发射结果。\\
\noindent 4. 写出最终完成周期。\\
\noindent 5. 区分依赖约束和资源约束。\\

\begin{quote}

\subsection*{一、三类依赖与寄存器重命名解析}
\addcontentsline{toc}{subsection}{一、三类依赖与寄存器重命名解析}


定义：

\begin{quote}
\footnotesize
\begin{verbatim}
RAW，Read After Write：前一条写，后一条读，是真实数据流依赖。
WAR，Write After Read：前一条读，后一条写，是复用同一存储位置产生的反依赖。
WAW，Write After Write：两条都写，是复用同一存储位置产生的输出依赖。
\end{verbatim}
\end{quote}

RAW 边：

\begin{center}
\includegraphics[width=0.88\linewidth]{figures/instruction-dependency-12.png}
\end{center}


\begin{quote}
\footnotesize
\begin{verbatim}
I1 -> I2，R1
I2 -> I5，R4
I4 -> I5，R1
\end{verbatim}
\end{quote}

WAR 边：

\begin{quote}
\footnotesize
\begin{verbatim}
I1 -> I3，I1 读 R2，I3 写 R2
I2 -> I4，I2 读 R1，I4 写 R1
\end{verbatim}
\end{quote}

WAW 边：

\begin{quote}
\footnotesize
\begin{verbatim}
I1 -> I4，二者都写 R1
\end{verbatim}
\end{quote}

重命名：

\begin{quote}
\footnotesize
\begin{verbatim}
I3: R11 = R6 + R7
I4: R12 = R8 + R9
I5: R10 = R4 + R12
\end{verbatim}
\end{quote}

重命名后，R2 的新值不再覆盖 I1 要读取的旧 R2，R1 的第二个定义也不再覆盖 I2 要读取的旧 R1。

一个合法重排：

\begin{quote}
\footnotesize
\begin{verbatim}
I1: R1  = R2 + R3
I3: R11 = R6 + R7
I4: R12 = R8 + R9
I2: R4  = R1 + R5
I5: R10 = R4 + R12
\end{verbatim}
\end{quote}

保留的真实依赖为 \texttt{I1->I2->I5} 和 \texttt{I4->I5}。

\subsection*{二、资源受限 List Scheduling 解析}
\addcontentsline{toc}{subsection}{二、资源受限 List Scheduling 解析}


无限资源下最早发射周期：

\begin{quote}
\footnotesize
\begin{verbatim}
ES(A)=0
ES(B)=0
ES(D)=0
ES(C)=max(0+2,0+1)=2
ES(E)=max(2+3,0+1)=5
ES(F)=5+2=7
\end{verbatim}
\end{quote}

从结点开始到出口完成的最长延迟：

\begin{quote}
\footnotesize
\begin{verbatim}
priority(F)=1
priority(E)=2+1=3
priority(C)=3+3=6
priority(D)=1+3=4
priority(A)=2+6=8
priority(B)=1+6=7
\end{verbatim}
\end{quote}

List Scheduling：

调度表：
\begin{center}\footnotesize
\begin{tabular}{lll}
周期 & 发射指令 & 说明\\
0 & A、B & A 延迟 2，B 延迟 1；满足每周期最多一条长延迟指令\\
1 & D & C 仍在等待 A 的结果\\
2 & C & A、B 均已完成\\
3、4 & 无 & 无就绪指令\\
5 & E & C 在周期 5 结果可用，D 早已完成\\
6 & 无 & 无就绪指令\\
7 & F & 发射 F
\end{tabular}
\end{center}


\begin{quote}
\footnotesize
\begin{verbatim}
周期 0：发射 A、B
  A 延迟 2，B 延迟 1；满足每周期最多一条长延迟指令。

周期 1：发射 D
  C 仍在等待 A 的结果。

周期 2：发射 C
  A、B 均已完成。

周期 3、4：无就绪指令

周期 5：发射 E
  C 在周期 5 结果可用，D 早已完成。

周期 6：无就绪指令

周期 7：发射 F
\end{verbatim}
\end{quote}

\texttt{F} 延迟为 1，因此在周期 8 完成，最终完成周期为 8。

约束区别：

\begin{quote}
\footnotesize
\begin{verbatim}
依赖约束由程序语义产生，消费者不能早于生产者结果可用。
资源约束由机器产生，例如发射宽度、功能部件数量和端口数量。
\end{verbatim}
\end{quote}

\subsection*{三、局部调度、全局调度与软件流水解析}
\addcontentsline{toc}{subsection}{三、局部调度、全局调度与软件流水解析}


真实依赖：

\begin{quote}
\footnotesize
\begin{verbatim}
L1 -> L3，Ra
L2 -> L3，Rb
L3 -> L4，Rx
L5 -> L6，新的 i 用于循环条件
\end{verbatim}
\end{quote}

地址 \texttt{a[i]、b[i]、x[i]} 都依赖本次迭代的 \texttt{i}。如果把 \texttt{L5} 提前，还必须保证 load/store 地址仍使用旧迭代的 \texttt{i}，通常需要为迭代索引建立不同版本。

局部调度：

\begin{quote}
\footnotesize
\begin{verbatim}
只在一个基本块内部移动指令。
它遵守块内 RAW/WAR/WAW 和资源约束，不跨条件分支或循环边。
\end{verbatim}
\end{quote}

全局调度：

\begin{quote}
\footnotesize
\begin{verbatim}
可以跨基本块移动指令，但要考虑控制依赖、异常、副作用、内存别名、执行频率以及补偿代码。
例如可能抛异常的 load 不能无条件移到原本不执行该 load 的路径上。
\end{verbatim}
\end{quote}

软件流水示意：

\begin{quote}
\footnotesize
\begin{verbatim}
周期 k：执行第 j 次迭代的 add/store，同时发射第 j+1 次迭代的两个 load。
需要为不同迭代使用不同的 Ra、Rb、Rx 版本，并保持每次 store 对应正确的索引。
稳态时，多次迭代的不同阶段在流水线上重叠。
\end{verbatim}
\end{quote}

寄存器压力：

\begin{quote}
\footnotesize
\begin{verbatim}
把 load 提前会让加载结果更早产生、更晚使用，扩大活跃区间。
多个迭代重叠时同时存活的值更多，需要更多寄存器；不足时会产生 spill。
\end{verbatim}
\end{quote}

Dom(Entry)={Entry}

\subsection*{五、循环 SSA 构造与退出 SSA 解析}
\addcontentsline{toc}{subsection}{五、循环 SSA 构造与退出 SSA 解析}


Dom 集：

\begin{quote}
\footnotesize
\begin{verbatim}
Dom(Entry)={Entry}
Dom(H)={Entry,H}
Dom(B)={Entry,H,B}
Dom(Exit)={Entry,H,Exit}
\end{verbatim}
\end{quote}

idom：

\begin{quote}
\footnotesize
\begin{verbatim}
idom(H)=Entry
idom(B)=H
idom(Exit)=H
\end{verbatim}
\end{quote}

Dominance Frontier：

\begin{quote}
\footnotesize
\begin{verbatim}
DF(B)={H}
DF(H)={H}
\end{verbatim}
\end{quote}

\texttt{H} 在自己的支配边界中，是因为 \texttt{H} 支配回边前驱 \texttt{B}，但不严格支配自身。

SSA：

\begin{quote}
\footnotesize
\begin{verbatim}
Entry:
  i0 = 0
  goto H

H:
  i1 = phi(i0,i2)
  if i1 < n goto B else Exit

B:
  i2 = i1 + 1
  goto H
\end{verbatim}
\end{quote}

phi 参数来源：

\begin{quote}
\footnotesize
\begin{verbatim}
i0 来自 Entry->H 边。
i2 来自 B->H 回边。
\end{verbatim}
\end{quote}

退出 SSA 的边复制：

\begin{quote}
\footnotesize
\begin{verbatim}
在 Entry->H 边插入：i1 = i0
在 B->H 边插入：i1 = i2
\end{verbatim}
\end{quote}

这些复制在对应前驱边上并行发生；之后寄存器合并可消除不必要的 move。
