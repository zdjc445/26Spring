### 一、词法分析与 LL(1) 分析答案

#### （一）词法分析

正则表达式是：

```text
(a|b)*a
```

它表示任意个 `a` 或 `b` 后面再接一个 `a`，也就是所有以 `a` 结尾的 `{a,b}` 串。

Thompson NFA 如图。起始状态为 `q0`，接受状态为 `q9`。

![Thompson NFA for (a|b)*a](figures/nfa-thompson-abstar-a.png)

NFA 转移表：

| 起点 | 边标号 | 终点 | 含义 |
| --- | --- | --- | --- |
| q0 | epsilon | q1 | 进入 `(a|b)*` |
| q0 | epsilon | q7 | `*` 重复 0 次 |
| q1 | epsilon | q2 | 选择 `a` 分支 |
| q1 | epsilon | q4 | 选择 `b` 分支 |
| q2 | a | q3 | 匹配 `a` |
| q4 | b | q5 | 匹配 `b` |
| q3 | epsilon | q6 | 分支结束 |
| q5 | epsilon | q6 | 分支结束 |
| q6 | epsilon | q1 | `*` 回到循环 |
| q6 | epsilon | q7 | `*` 退出循环 |
| q7 | epsilon | q8 | 连接最后一个 `a` |
| q8 | a | q9 | 匹配末尾 `a` |

子集构造从初态闭包开始：

```text
D0 = epsilon-closure({q0}) = {q0,q1,q2,q4,q7,q8}
```

逐步计算：

| DFA 状态 | NFA 状态集合 | 输入 a 后 | 输入 b 后 | 是否接受 |
| --- | --- | --- | --- | --- |
| D0 | `{q0,q1,q2,q4,q7,q8}` | D1 | D2 | 否 |
| D1 | `{q1,q2,q3,q4,q6,q7,q8,q9}` | D1 | D2 | 是 |
| D2 | `{q1,q2,q4,q5,q6,q7,q8}` | D1 | D2 | 否 |

接受状态判断依据：NFA 状态集合中包含 `q9`。因此只有 `D1` 是 DFA 接受状态。

![子集构造 DFA for (a|b)*a](figures/dfa-subset-abstar-a.png)

最小化时先按终态与非终态分组：

```text
P0 = { {D1}, {D0,D2} }
```

比较 `D0` 和 `D2`：

| 状态 | 输入 a | 输入 b | 结论 |
| --- | --- | --- | --- |
| D0 | D1 | D2 | a 到终态组，b 到非终态组 |
| D2 | D1 | D2 | a 到终态组，b 到非终态组 |

`D0` 和 `D2` 对所有输入都转到相同分组，所以等价，可以合并。令：

```text
N = {D0,D2}
F = {D1}
```

最小 DFA：

| 最小状态 | 输入 a | 输入 b | 是否接受 |
| --- | --- | --- | --- |
| N | F | N | 否 |
| F | F | N | 是 |

![最小 DFA for (a|b)*a](figures/dfa-min-abstar-a.png)

#### （二）LL(1) 分析

原文法：

```text
A -> B C
B -> B p | r
C -> t | u
```

`B -> B p | r` 是直接左递归。套用：

```text
X  -> X alpha | beta
X  -> beta X'
X' -> alpha X' | epsilon
```

其中 `alpha=p`，`beta=r`，得到：

```text
A  -> B C
B  -> r B'
B' -> p B' | epsilon
C  -> t | u
```

FIRST 集：

| 非终结符 | 推导依据 | FIRST |
| --- | --- | --- |
| B | `B -> r B'` | `{ r }` |
| B' | `B' -> p B' | epsilon` | `{ p, epsilon }` |
| C | `C -> t | u` | `{ t, u }` |
| A | `A -> B C`，B 不能推出 epsilon | `{ r }` |

FOLLOW 集：

| FOLLOW 集 | 推导依据 | 结果 |
| --- | --- | --- |
| FOLLOW(A) | A 是开始符号 | `{ $ }` |
| FOLLOW(B) | `A -> B C`，B 后面是 C | `{ t, u }` |
| FOLLOW(B') | `B -> r B'`，B' 在末尾 | `{ t, u }` |
| FOLLOW(C) | `A -> B C`，C 在末尾 | `{ $ }` |

预测分析表填表依据：

| 产生式 | 依据 | 表项 |
| --- | --- | --- |
| `A -> B C` | FIRST(BC)={r} | `M[A,r]` |
| `B -> r B'` | FIRST(rB')={r} | `M[B,r]` |
| `B' -> p B'` | FIRST(pB')={p} | `M[B',p]` |
| `B' -> epsilon` | FOLLOW(B')={t,u} | `M[B',t]`，`M[B',u]` |
| `C -> t` | FIRST(t)={t} | `M[C,t]` |
| `C -> u` | FIRST(u)={u} | `M[C,u]` |

完整预测分析表，空白处为 error：

| 非终结符 | r | p | t | u | $ |
| --- | --- | --- | --- | --- | --- |
| A | `A -> B C` | error | error | error | error |
| B | `B -> r B'` | error | error | error | error |
| B' | error | `B' -> p B'` | `B' -> epsilon` | `B' -> epsilon` | error |
| C | error | error | `C -> t` | `C -> u` | error |

每个表项最多一条产生式，因此改写后的文法是 LL(1)。

### 二、LR 分析与语义分析答案

#### （一）SLR 分析

增广文法：

```text
(0) S' -> S
(1) S  -> C C
(2) C  -> c C
(3) C  -> d
```

规范 LR(0) 项集族：

```text
I0:
S' -> . S
S  -> . C C
C  -> . c C
C  -> . d

I1:
S' -> S .

I2:
S  -> C . C
C  -> . c C
C  -> . d

I3:
C  -> c . C
C  -> . c C
C  -> . d

I4:
C  -> d .

I5:
S  -> C C .

I6:
C  -> c C .
```

GOTO 转移表：

| 来源 | 符号 | 目标 |
| --- | --- | --- |
| I0 | S | I1 |
| I0 | C | I2 |
| I0 | c | I3 |
| I0 | d | I4 |
| I2 | C | I5 |
| I2 | c | I3 |
| I2 | d | I4 |
| I3 | C | I6 |
| I3 | c | I3 |
| I3 | d | I4 |

FOLLOW：

| 非终结符 | 推导依据 | FOLLOW |
| --- | --- | --- |
| S | S 是开始符号 | `{ $ }` |
| C | `S -> C C`：第一个 C 后接 C，加入 FIRST(C)={c,d}；第二个 C 在末尾，加入 FOLLOW(S) | `{ c,d,$ }` |

SLR 填表规则：

```text
点前进到终结符时填 shift。
完成项 A -> alpha . 只在 FOLLOW(A) 上填 reduce。
S' -> S . 在 $ 上填 acc。
```

完整 SLR ACTION/GOTO 表：

| 状态 | ACTION(c) | ACTION(d) | ACTION($) | GOTO(S) | GOTO(C) |
| --- | --- | --- | --- | --- | --- |
| 0 | s3 | s4 | error | 1 | 2 |
| 1 | error | error | acc | error | error |
| 2 | s3 | s4 | error | error | 5 |
| 3 | s3 | s4 | error | error | 6 |
| 4 | r3 | r3 | r3 | error | error |
| 5 | error | error | r1 | error | error |
| 6 | r2 | r2 | r2 | error | error |

冲突判断：表中没有任何单元格同时出现 shift 和 reduce，也没有任何单元格同时出现两个 reduce，所以不存在移进-规约冲突或规约-规约冲突。

#### （二）L 属性 SDD

设计思路：`T.type` 是类型来源，向右传给 `L.in` 和 `L'.in`，每遇到一个 `id` 就把该名字和传入类型加入符号表。

| 产生式 | 语义规则或动作 |
| --- | --- |
| `D -> T L` | `L.in = T.type` |
| `T -> int` | `T.type = int` |
| `T -> float` | `T.type = float` |
| `L -> id L'` | `addType(id.name, L.in)`；`L'.in = L.in` |
| `L' -> , id L'1` | `addType(id.name, L'.in)`；`L'1.in = L'.in` |
| `L' -> epsilon` | 不执行插入动作 |

输入 `float x, y` 的属性传递：

| 步骤 | 动作 | 结果 |
| --- | --- | --- |
| 1 | `T -> float` | `T.type=float` |
| 2 | `D -> T L` | `L.in=float` |
| 3 | 识别 `x` | `addType(x,float)` |
| 4 | 进入 `L'` | `L'.in=float` |
| 5 | 识别 `y` | `addType(y,float)` |

最终符号表：

| 名字 | 类型 |
| --- | --- |
| x | float |
| y | float |

继承属性只依赖父结点或左侧兄弟结点，因此满足 L 属性限制。

### 三、中间代码、控制流与 SSA 答案

#### 1. 三地址码

数组元素宽度为 4，`a[i]` 的地址偏移为 `i * 4`。

```text
L1:
if i < n goto L2
goto L6

L2:
t1 = i * 4
t2 = a[t1]
if t2 > 0 goto L3
goto L4

L3:
sum = sum + t2
goto L4

L4:
i = i + 1
goto L1

L6:
```

#### 2. 基本块与 CFG

![基本块 CFG](figures/cfg-09-basic-blocks.png)

| 基本块 | 语句 |
| --- | --- |
| B1 | `L1` 条件判断，真到 B2，假到 B5 |
| B2 | 数组地址计算、读取和 `a[i] > 0` 判断 |
| B3 | `sum = sum + t2` |
| B4 | `i = i + 1`，回到 B1 |
| B5 | `L6` 循环出口 |

CFG 边：

```text
B1 -> B2
B1 -> B5
B2 -> B3
B2 -> B4
B3 -> B4
B4 -> B1
```

#### 3. SSA

循环头 B1 有来自循环外和回边 B4 的两条路径，因此 `i` 和 `sum` 都需要 phi。B4 还有来自 B2 假分支和 B3 真分支的汇合，因此 `sum` 在 B4 也需要 phi。

```text
L1:
i1   = phi(i0, i2)
sum1 = phi(sum0, sum3)
if i1 < n goto L2
goto L6

L2:
t1 = i1 * 4
t2 = a[t1]
if t2 > 0 goto L3
goto L4

L3:
sum2 = sum1 + t2
goto L4

L4:
sum3 = phi(sum1, sum2)
i2 = i1 + 1
goto L1

L6:
```

#### 4. 退出 SSA 的复制边

phi 展开原则：在每条前驱边上插入对应复制。

| phi | 前驱边 | 插入复制 |
| --- | --- | --- |
| `i1 = phi(i0, i2)` | 循环外 -> L1 | `i1 = i0` |
| `i1 = phi(i0, i2)` | L4 -> L1 | `i1 = i2` |
| `sum1 = phi(sum0, sum3)` | 循环外 -> L1 | `sum1 = sum0` |
| `sum1 = phi(sum0, sum3)` | L4 -> L1 | `sum1 = sum3` |
| `sum3 = phi(sum1, sum2)` | L2 -> L4 | `sum3 = sum1` |
| `sum3 = phi(sum1, sum2)` | L3 -> L4 | `sum3 = sum2` |

这些复制在语义上是并行复制；若控制流边不能直接插入指令，需要拆分边。

### 四、运行时环境与目标代码生成答案

#### （一）运行时环境

`add` 的活动记录至少包含：

| 内容 | 作用 |
| --- | --- |
| 参数 `a`、`b` | 被调用函数读取实参 |
| 局部变量 `t` | 保存 `a+b` 的局部结果 |
| 返回地址 | 指出 `add` 返回后继续执行的位置 |
| 旧 BP / 控制链 | 返回时恢复调用者活动记录 |
| 保存的寄存器 | 保护调用前的机器状态 |
| 返回值位置 | 按调用约定传回 `t` |

参数从右到左压栈，调用 `add(x,y)` 的顺序是：

| 顺序 | 动作 |
| --- | --- |
| 1 | 压入 `y` 的值，作为形参 `b` |
| 2 | 压入 `x` 的值，作为形参 `a` |
| 3 | 执行 `call add`，保存返回地址 |
| 4 | 被调函数建立新活动记录 |

BP、SP、返回地址、返回值作用：

| 项 | 作用 |
| --- | --- |
| SP | 指向当前栈顶，压栈和退栈会改变 SP |
| BP | 当前活动记录的稳定基址，用固定偏移访问参数和局部变量 |
| 返回地址 | 被调函数结束后跳回调用点 |
| 返回值 | 放入约定寄存器或栈中约定位置，供调用者读取 |

垃圾回收比较：

| 方法 | 优点 | 缺点 |
| --- | --- | --- |
| 引用计数 | 对象计数变为 0 时可立即回收 | 无法回收不可达环 |
| 标记-清扫 | 从根集标记可达对象，能回收不可达环 | 需要遍历堆，可能产生暂停 |

引用计数无法处理的结构是不可达循环引用，例如两个对象互相引用但已经没有根指向它们。

#### （二）目标代码生成

三地址码：

```text
t1 = a - b
t2 = t1 + c
x  = t2
```

目标代码：

```text
LD  R0, a
LD  R1, b
SUB R0, R1
LD  R1, c
ADD R0, R1
ST  x, R0
```

寄存器描述符变化：

| 步骤 | 指令 | R0 | R1 |
| --- | --- | --- | --- |
| 初始 | - | `{}` | `{}` |
| 1 | `LD R0,a` | `{a}` | `{}` |
| 2 | `LD R1,b` | `{a}` | `{b}` |
| 3 | `SUB R0,R1` | `{t1}` | `{b}` |
| 4 | `LD R1,c` | `{t1}` | `{c}` |
| 5 | `ADD R0,R1` | `{t2}` | `{c}` |
| 6 | `ST x,R0` | `{t2,x}` | `{c}` |

最终地址描述符中：

```text
Addr(x) = {内存位置 x, R0}
```

### 五、数据流分析、支配与自然循环答案

#### 1. 到达定值分析框架

到达定值是正向 may 分析：

```text
IN[B]  = union OUT[P]，P 是 B 的所有前驱
OUT[B] = gen[B] union (IN[B] - kill[B])
```

初始化按题目要求从空集开始。

#### 2. gen/kill

所有定义：

```text
d1: x = 1
d2: y = 2
d3: z = x + y
d4: x = z
```

`d1` 和 `d4` 都定义 `x`，互相 kill。

| 基本块 | gen | kill |
| --- | --- | --- |
| B1 | `{d1,d2}` | `{d4}` |
| B2 | `{d3}` | `{}` |
| B3 | `{d4}` | `{d1}` |
| B4 | `{}` | `{}` |

#### 3. IN/OUT 不动点结果

| 基本块 | IN | OUT |
| --- | --- | --- |
| B1 | `{}` | `{d1,d2}` |
| B2 | `{d1,d2,d3,d4}` | `{d1,d2,d3,d4}` |
| B3 | `{d1,d2,d3,d4}` | `{d2,d3,d4}` |
| B4 | `{d1,d2,d3,d4}` | `{d1,d2,d3,d4}` |

关键推导：

```text
IN[B2] = OUT[B1] union OUT[B3]
       = {d1,d2} union {d2,d3,d4}
       = {d1,d2,d3,d4}
```

所以循环回边使 `d3`、`d4` 也能到达 B2。

#### 4. 支配集合和直接支配者

支配定义：从 Entry 到某节点的每条路径都经过的节点，才支配该节点。

| 节点 | Dom |
| --- | --- |
| Entry | `{Entry}` |
| B1 | `{Entry,B1}` |
| B2 | `{Entry,B1,B2}` |
| B3 | `{Entry,B1,B2,B3}` |
| B4 | `{Entry,B1,B2,B4}` |
| Exit | `{Entry,B1,B2,B4,Exit}` |

直接支配者：

| 节点 | idom |
| --- | --- |
| B1 | Entry |
| B2 | B1 |
| B3 | B2 |
| B4 | B2 |
| Exit | B4 |

#### 5. 回边与自然循环

回边判断：若边 `n -> h` 中 `h` 支配 `n`，则该边是回边。

CFG 中：

```text
B3 -> B2
```

因为 `B2` 支配 `B3`，所以 `B3 -> B2` 是回边。

自然循环构造：从回边尾 `B3` 反向追溯前驱，直到回边头 `B2`，并包含头和尾：

```text
自然循环 = {B2, B3}
```
