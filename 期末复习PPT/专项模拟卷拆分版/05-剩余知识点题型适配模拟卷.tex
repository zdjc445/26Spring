\subsection*{三、过程型小题：LR 表格驱动分析器（20 分）}
\addcontentsline{toc}{subsection}{三、过程型小题：LR 表格驱动分析器（20 分）}

已知某 LR 分析表有如下条目：

\begin{quote}
\footnotesize
\begin{verbatim}
ACTION[0,id] = s1
ACTION[1,+]  = r(E -> id)
ACTION[1,$]  = r(E -> id)
ACTION[2,+]  = s3
ACTION[2,$]  = acc
ACTION[3,id] = s4
ACTION[4,$]  = r(E -> E + id)

GOTO[0,E] = 2
\end{verbatim}
\end{quote}

输入串：

\begin{quote}
\footnotesize
\begin{verbatim}
id + id $
\end{verbatim}
\end{quote}

要求：

\noindent 1. 说明 ACTION 表和 GOTO 表分别在什么时候使用。\\
\noindent 2. 写出分析过程中栈和输入的大致变化。\\
\noindent 3. 说明什么时候接受输入。\\

\subsection*{四、次级流程题：通用左递归消除（20 分）}
\addcontentsline{toc}{subsection}{四、次级流程题：通用左递归消除（20 分）}

文法：

\begin{quote}
\footnotesize
\begin{verbatim}
S -> A a | b
A -> S d | c
\end{verbatim}
\end{quote}

按非终结符顺序：

\begin{quote}
\footnotesize
\begin{verbatim}
S, A
\end{verbatim}
\end{quote}

\noindent 1. 判断该文法是否存在间接左递归。\\
\noindent 2. 按通用左递归消除思路，先把 \texttt{A -> S d} 中的 \texttt{S} 用 \texttt{S} 的产生式替换。\\
\noindent 3. 消除替换后 \texttt{A} 的直接左递归。\\

\section*{B 简明答案}
\addcontentsline{toc}{section}{B 简明答案}

\subsection*{一、背景型简答答案}
\addcontentsline{toc}{subsection}{一、背景型简答答案}

高层 IR 和低层 IR：

\begin{quote}
\footnotesize
\begin{verbatim}
高层 IR 保留较多源语言结构，例如循环、函数、对象等，便于前端语义分析和高层优化。
低层 IR 更接近机器，例如显式跳转、加载/存储、寄存器或栈操作，便于后端代码生成。
\end{verbatim}
\end{quote}

DFA 比 NFA 更容易直接执行：

\begin{quote}
\footnotesize
\begin{verbatim}
DFA 在每个状态、每个输入符号上最多只有一个确定转移。
NFA 可能有多个转移和 epsilon 转移，直接模拟时要维护一组可能状态。
因此 DFA 执行时只需要维护一个当前状态。
\end{verbatim}
\end{quote}

SSA 有利于优化：

\begin{quote}
\footnotesize
\begin{verbatim}
SSA 中每个变量版本只赋值一次，定义和使用关系清楚。
这有利于常量传播、死代码删除、公共子表达式消除等优化。
\end{verbatim}
\end{quote}

工业编译器使用 SSA 或类似形式的原因：

\begin{quote}
\footnotesize
\begin{verbatim}
SSA 能简化数据流分析，让优化算法更容易实现。
实际编译器在后端会把 phi 函数转换成复制、寄存器分配或其它等价低层操作。
\end{verbatim}
\end{quote}

\subsection*{二、理论细节答案}
\addcontentsline{toc}{subsection}{二、理论细节答案}

SDD 和 SDT：

\begin{quote}
\footnotesize
\begin{verbatim}
SDD 是语法制导定义，偏抽象，描述文法符号有哪些属性以及属性如何计算。
SDT 是语法制导翻译，偏实现，把语义动作嵌入到产生式中，说明分析过程中何时执行动作。
\end{verbatim}
\end{quote}

属性文法和带副作用语义动作：

\begin{quote}
\footnotesize
\begin{verbatim}
属性文法主要通过属性之间的依赖计算语义信息，不依赖修改全局状态。
带副作用语义动作可能会修改符号表、输出代码或更新全局结构。
\end{verbatim}
\end{quote}

依赖图中有环时无法求值：

\begin{quote}
\footnotesize
\begin{verbatim}
如果属性 A 依赖属性 B，同时 B 又直接或间接依赖 A，就没有合法的先后计算顺序。
依赖图存在环时，无法得到拓扑序，因此属性值无法正常求出。
\end{verbatim}
\end{quote}

受控副作用：

\begin{quote}
\footnotesize
\begin{verbatim}
受控副作用是指语义动作虽然会修改外部状态，但执行位置和执行顺序明确，并且不破坏属性求值。
基本要求包括：
1. 副作用执行前所需属性已经计算完成。
2. 副作用不会引入依赖环。
3. 副作用不会因分析顺序不确定而重复执行或漏执行。
\end{verbatim}
\end{quote}

\subsection*{三、过程型小题答案}
\addcontentsline{toc}{subsection}{三、过程型小题答案}

ACTION 和 GOTO：

\begin{quote}
\footnotesize
\begin{verbatim}
ACTION[state, 终结符] 用于面对输入符号时决定移进、规约或接受。
GOTO[state, 非终结符] 用于规约出非终结符之后决定进入哪个状态。
\end{verbatim}
\end{quote}

分析过程：

\begin{quote}
\footnotesize
\begin{verbatim}
状态栈        符号栈        输入           动作
0             空            id + id $      ACTION[0,id] = s1
0 1           id            + id $         ACTION[1,+] = r(E -> id)
0 2           E             + id $         GOTO[0,E] = 2
0 2 3         E +           id $           ACTION[2,+] = s3
0 2 3 4       E + id        $              ACTION[3,id] = s4
0 2 3 4       E + id        $              ACTION[4,$] = r(E -> E + id)
0 2           E             $              ACTION[2,$] = acc
\end{verbatim}
\end{quote}

说明：

\begin{quote}
\footnotesize
\begin{verbatim}
接受条件是当前状态和输入结束符 $ 对应的 ACTION 表项为 acc。
\end{verbatim}
\end{quote}

\subsection*{四、通用左递归消除答案}
\addcontentsline{toc}{subsection}{四、通用左递归消除答案}

原文法：

\begin{quote}
\footnotesize
\begin{verbatim}
S -> A a | b
A -> S d | c
\end{verbatim}
\end{quote}

存在间接左递归：

\begin{quote}
\footnotesize
\begin{verbatim}
S => A a => S d a
\end{verbatim}
\end{quote}

按顺序 \texttt{S, A}，处理 \texttt{A} 时，把 \texttt{A -> S d} 中的 \texttt{S} 替换为 \texttt{S} 的右部：

\begin{quote}
\footnotesize
\begin{verbatim}
A -> A a d | b d | c
\end{verbatim}
\end{quote}

此时 \texttt{A} 有直接左递归：

\begin{quote}
\footnotesize
\begin{verbatim}
A -> A a d | b d | c
\end{verbatim}
\end{quote}

消除直接左递归：

\begin{quote}
\footnotesize
\begin{verbatim}
A  -> b d A' | c A'
A' -> a d A' | epsilon
\end{verbatim}
\end{quote}

最终文法：

\begin{quote}
\footnotesize
\begin{verbatim}
S  -> A a | b
A  -> b d A' | c A'
A' -> a d A' | epsilon
\end{verbatim}
\end{quote}

\subsection*{五、数组类型 L 属性定义答案}
\addcontentsline{toc}{subsection}{五、数组类型 L 属性定义答案}

语义规则：

\begin{quote}
\footnotesize
\begin{verbatim}
T -> B C
  C.in = B.type
  T.type = C.type

B -> int
  B.type = int

B -> float
  B.type = float

C -> [ num ] C1
  C1.in = array(num.val, C.in)
  C.type = C1.type

C -> epsilon
  C.type = C.in
\end{verbatim}
\end{quote}

对 \texttt{int[10][20]}：

\begin{quote}
\footnotesize
\begin{verbatim}
B.type = int
C.in = int

读到 [10]：
C1.in = array(10, int)

读到 [20]：
C2.in = array(20, array(10, int))

C2 -> epsilon：
C2.type = array(20, array(10, int))
\end{verbatim}
\end{quote}

最终：

\begin{quote}
\footnotesize
\begin{verbatim}
T.type = array(20, array(10, int))
\end{verbatim}
\end{quote}

说明：

\begin{quote}
\footnotesize
\begin{verbatim}
该写法按从左到右的语义动作构造类型。
如果课程约定数组类型按相反嵌套顺序表示，卷面应按老师 PPT 中的记法调整。
\end{verbatim}
\end{quote}
